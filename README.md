# Открытые LLM на казахских нормативных документах

Мы сравнили 9 открытых языковых моделей на вопросах по 40 нормативным актам Республики Казахстан на казахском языке: 36 указам Президента и 4 законам 2026 года из открытого источника [zan.kz](https://zan.kz). Проверяли четыре вещи:

- находит ли модель ответ в документе;
- выдумывает ли она ответ, если его в документе нет;
- что меняется, если вопрос задан по-русски;
- что даёт адаптация Llama 3.1 к казахскому языку.

Всё запускалось локально в Ollama: 1 810 задач на модель, всего 16 290 ответов. Ответы оценивал судья-LLM.

Статья на Хабре: *[ссылка будет добавлена]*. Полная методика: [docs/experiment_protocol.md](docs/experiment_protocol.md).

## Кратко о результатах

Ниже — оценка судьи `gpt-oss:120b` (версия промпта j3), % ответов. Звёздочкой отмечена справочная модель: она же была судьёй и в основное сравнение не входит.

|---|---|---|---|---|---|
| Llama-3.1-70B Instruct Q4 | **91,6** | 0,0 | 82,4 | 32,5 | 67,5 |
| KazLLM-1.0-70B | 90,1 | 2,1 | **83,3** | 17,5 | 43,0 |
| gemma4 (8B) | 84,8 | 5,7 | 81,8 | **8,0** | **10,0** |
| KazLLM-1.0-8B | 82,7 | 6,1 | 68,7 | 21,5 | 19,5 |
| Sherkala-8B-Chat | 81,3 | 7,9 | 74,0 | 13,0 | 33,5 |
| qwen3-8B | 72,8 | 12,6 | 59,0 | 10,5 | 13,5 |
| Llama-3.1-8B Instruct F16 | 65,5 | 24,4 | 52,9 | 15,0 | 24,0 |
| Llama-3.1-8B Instruct Q4 | 58,4 | 30,9 | 45,4 | 12,0 | 17,5 |
| gpt-oss-120b* | 88,4 | 2,4 | 82,4 | 10,0 | 10,0 |

- **Точнее всех модели на 70B, но они же больше всех выдумывают.** Особенно на русских вопросах, когда ответа в документе нет.
- **Лучшая из 8B-моделей — gemma4.** Она точнее специализированных казахских 8B-моделей и галлюцинирует реже всех.
- **Адаптация к казахскому на 8B в основном убирает ложные отказы:** у Llama-8B Q4 их 31 %, у KazLLM-8B — 6 %.
- **На 70B адаптация почти не меняет точность, но вдвое снижает галлюцинации:** 32,5 % → 17,5 %.
- **Лексическая метрика «эталон дословно в ответе» занижает точность примерно в 2 раза**, поэтому выводы сделаны по оценке судьи.

Рисунки лежат в [reports/figures/](reports/figures/), все сводные цифры — в [reports/numbers.json](reports/numbers.json).

## Эксперименты

| Код | Что подаётся модели | Задач |
|---|---|---|
| E1 | Вопрос на казахском + казахский документ, ответ в документе есть | 705 |
| E3 | Тот же вопрос на русском + тот же документ | 705 |
| E2 | То же окно документа, но строки с ответом (±2 строки) вырезаны; вопрос на казахском | 200 |
| E2_ru | То же, вопрос на русском | 200 |

Для всех моделей одинаковы окно контекста (8 192 токена), системный промпт и параметры: `temperature 0`, `seed 42`, `num_predict 512`, `truncate false`. Промпт каждой задачи побайтово одинаков для всех моделей и проверен на точное число токенов у каждой из них.

## Что понадобится

- Сервер Ollama версии не ниже 0.32. Мы использовали ASUS Ascent GX10 (NVIDIA GB10, 128 ГБ единой памяти). Для 70B-моделей нужно около 48 ГБ памяти GPU, для gpt-oss-120b — около 65 ГБ.
- Python 3.10 или новее.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env            # HOST=http://<адрес Ollama>:11434

# Модели (теги — как в config.yaml)
ollama pull gemma4:latest
ollama pull qwen3:8b
ollama pull huggingface.co/issai/LLama-3.1-KazLLM-1.0-8B-GGUF4
ollama pull huggingface.co/issai/LLama-3.1-KazLLM-1.0-70B-GGUF4
ollama pull llama3.1:8b-instruct-q4_K_M
ollama pull llama3.1:8b-instruct-fp16
ollama pull llama3.1:70b-instruct-q4_K_M
ollama pull gpt-oss:120b
ollama pull hf.co/DiDustin/sherkala_gguf:F16
ollama create sherkala-chat -f models/sherkala-chat.Modelfile   # чат-шаблон Llama 3.1, протокол п. 2.1
```

Готовые задачи (`tasks/`) и все ответы моделей (`results/main/`) уже лежат в репозитории. Чтобы пересчитать цифры и рисунки, сервер не нужен:

```bash
python make_article_figs.py          # -> reports/article/fig*.png, numbers.json
python interim_report.py             # лексические метрики, скорость, контроль данных
```

Полный цикл с нуля:

```bash
python main.py build                                 # 1. замороженные задачи E1/E3 -> tasks/
python build_e2_cut.py --n 200                       # 2. задачи E2/E2_ru (вырезка ответа)
python main.py run --exp e1 e3 e2 e2_ru --run-id main   # 3. прогон всех моделей из config.yaml
python bench_speed.py --run-id main                  # 4. скорость prefill/TTFT на холодном кэше
python evaluate.py --judge gpt-oss:120b --think low --tag j3   # 5. оценка судьёй
python make_article_figs.py                          # 6. сводка и рисунки
```

Прогон и оценку можно прерывать: уже записанные ответы при повторном запуске пропускаются. Чтобы добавить новую модель, не пересобирая задачи, пропишите её в `config.yaml` и выполните `python add_models.py --models <тег>`, затем `python main.py run --models <тег>`.

Учтите, что шаг 1 заново подбирает окна под набор моделей в `config.yaml`. Если набор моделей другой, окна и промпты получатся другими. Чтобы воспроизвести опубликованные цифры, используйте готовые `tasks/`.

## Скрипты

| Файл | Что делает |
|---|---|
| `main.py` | Точка входа: `build` (сборка задач) и `run` (прогон) |
| `config.yaml` | Модели, параметры генерации, seed, пути |
| `prompts.py` | Системный промпт (на казахском) и фраза отказа |
| `build_tasks.py` | Проверяет хеши документов, считает токены каждой модели, строит окна контекста вокруг ответа, замораживает задачи E1/E3 и manifest |
| `build_e2_cut.py` | Собирает E2/E2_ru: вырезает строки ответа из окон E1 и отсеивает вопросы, где ответ мог остаться в тексте |
| `add_models.py` | Добавляет модель в готовые задачи: точно считает токены и проверяет лимит, окна не меняет |
| `run_experiment.py` | Прогон: сверка хеша документа перед каждым запросом, стрим `/api/chat`, запись ответа и всех метрик Ollama в JSONL |
| `bench_speed.py` | Отдельный замер prefill и TTFT без кэша префиксов (уникальная метка в начале промпта) |
| `evaluate.py` | Судья-LLM: JSON-схема ответа, метки для E1/E3 и E2, повторы со сменой seed и уровня рассуждения |
| `interim_report.py` | Лексические метрики (эталон в ответе, полнота, F1), эвристика отказа, язык ответа, скорость, контроль данных |
| `make_validation_sample.py` | Стратифицированная выборка 200 ответов и лист xlsx для ручной проверки судьи |
| `validate_judge.py` | Сверка судьи с ручной разметкой: согласие, каппа Коэна, матрицы ошибок (`reports/judge_validation.json`) |
| `make_article_figs.py` | Сводные цифры (`numbers.json`) и рисунки статьи |
| `utils/ollama_client.py` | Клиент Ollama: стрим с метриками, точный подсчёт токенов через `truncate=false` |
| `utils/context_builder.py` | Окно контекста из целых строк вокруг ответа; случайная позиция ответа (воспроизводима по seed) |
| `utils/doc_store.py` | Проверка SHA-256 и построчное чтение PDF (PyMuPDF) |
| `models/sherkala-chat.Modelfile` | Обёртка Sherkala с чат-шаблоном и stop-токенами Llama 3.1 (веса не меняются) |

## Данные

| Путь | Содержимое |
|---|---|
| `documents/` | 40 PDF нормативных актов (источник — zan.kz) |
| `dataset/qa_kk.json`, `qa_ru.json` | 705 вопросов с эталонным ответом и номерами строк документа; русские переводы (связь по `source_id`) |
| `dataset/qa_kk_negative.json` | Вопросы не по теме (архивный эксперимент `e2_offtopic`, в статью не вошёл: все модели отказываются на 100 %) |
| `tasks/*.jsonl`, `tasks/manifest.json` | Замороженные задачи: окно, промпт, `prompt_sha256`, точное число токенов у каждой модели |
| `results/main/<эксп>/<модель>.jsonl` | Ответы моделей как есть плюс метрики (digest модели, хеш документа, токены, скорость, TTFT и др.) |
| `results/main/speed/` | Замер скорости на холодном кэше |
| `results/main/judge/gpt-oss_120b_j3/` | Вердикты судьи с обоснованием, рассуждением и sha промпта судьи |
| `reports/validation_*.jsonl` | Выборка для ручной проверки судьи, ключ к ней (какая модель ответила) и ручная разметка первых 100 ответов: исходная метка, метка после разбора и пояснение |

## Ограничения

- **Оценивал LLM-судья.** Вердикты при рассуждении low и medium совпадают в 92,5 % и 87,5 % случаев. На 100 ответах, размеченных вручную, после разбора расхождений судья совпадает с человеком в 94,6 % (ответ есть, каппа 0,89) и 93,2 % (ответ вырезан, каппа 0,88). По исходной разметке — 71 % и 77 %: большинство расхождений оказались ошибками разметчика. Разметчик один, выборка стратифицированная. Подробности — `python validate_judge.py`.
- **Домен один, промпт один, декодирование жадное.**
- **Sherkala запускалась через собственную обёртку** с чат-шаблоном Llama 3.1.
